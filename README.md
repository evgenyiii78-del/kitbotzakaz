# @zakazKiT_bot — уведомления о новых заказах Flowwow Seller

**Назначение:** только чтение заказов Flowwow и отправка уведомлений в Telegram. Бот не принимает и не отменяет заказы.

## Развёртывание на Bothost

1. Подключите этот GitHub-репозиторий в Bothost как Python-проект. Главный файл: `main.py`, зависимости: `requirements.txt`.
2. Подключите существующего Telegram-бота **@zakazKiT_bot**. Токен получите в @BotFather. Если бот уже запущен на Bothost, замените существующее развёртывание — не запускайте два процесса с одним токеном.
3. В разделе «Переменные окружения» добавьте:
   - `FLOWWOW_TOKEN` — токен Flowwow API из кабинета продавца. Не публикуйте его.
   - `BOT_TOKEN` — токен Telegram. Если Bothost сам задаёт переменную, повторять не нужно.
   - `SETUP_CODE` — придуманный вами секретный код длиной **не менее 8 символов**.
   - `DATABASE_PATH` — `/app/data/flowwow_orders.db`.
   - `POLL_SECONDS` — `30` (по умолчанию; при ограничениях API увеличьте).
   - `LOOKBACK_DAYS` — `2` (от 1 до 7 дней, по умолчанию 2).
   - `MAX_OLDER_CHECKS` — `10` (старых незавершённых заказов за цикл; от 1 до 30).
4. Запустите бот. В Telegram откройте https://t.me/zakazKiT_bot, нажмите «Старт» и отправьте `/connect ВАШ_КОД`.
5. Проверьте `/test` (тест Telegram), `/status` (состояние) и `/last` (последний сохранённый заказ). После первой успешной проверки Flowwow бот сообщит, что мониторинг подключён.


## Уведомления в Telegram-группе

1. **Не отключайте существующую личную привязку** через `/connect`: только этот пользователь управляет ботом.
2. Создайте Telegram-группу или откройте существующую и добавьте `@zakazKiT_bot` в участники. Разрешите боту отправлять сообщения.
3. В **этой группе** со своего Telegram-аккаунта отправьте **`/bindgroup@zakazKiT_bot`**. Отправлять `SETUP_CODE` в группу **не нужно**.
4. Бот подтвердит подключение, и **следующие новые заказы будут приходить в группу вместо личного чата**.
5. В группе владелец может использовать `/last@zakazKiT_bot`, `/status@zakazKiT_bot`, `/test@zakazKiT_bot`. В личном чате работают обычные команды без упоминания.
6. Для возврата уведомлений в личный чат отправьте боту **`/private`** в личной переписке. Можно также отправить `/unbindgroup@zakazKiT_bot` в подключённой группе.
7. В личном чате команда `/group` показывает, куда направляются уведомления.

**Важные особенности:**
- **Все участники подключённой группы смогут читать уведомления**, в том числе состав заказа, адрес и комментарии, если эти поля приходят из Flowwow. Для конфиденциальности лучше использовать отдельную закрытую группу сотрудников.
- Команды и смена получателя доступны только владельцу, который привязал бота лично. Сообщения из чужих групп игнорируются.
- Для команд в группе используется суффикс `@zakazKiT_bot` — он работает со стандартным Privacy Mode Telegram, без отключения защиты через BotFather.
- Поддерживается **одна группа**; повторная `/bindgroup` переключит уведомления в новую группу.
- Хранилище SQLite и история заказов сохраняются при переключении адресата, если на Bothost сохранена прежняя папка `/app/data`.

## Как работают уведомления

- Бот опрашивает API Flowwow каждые 30 секунд и проверяет активные магазины.
- При первой синхронизации уже созданные заказы помечаются как известные, без отправки старых уведомлений.
- Команда `/last` вручную показывает самый свежий заказ из локальной базы, полученной из Flowwow. Это не повторное уведомление и не новый API-запрос; данные обновляются при очередной проверке, обычно раз в 30 секунд.
- При появлении нового ID заказа отправляет сообщение с товарами, датой, стоимостью и комментариями, если поля есть в API.
- Защита от повторов и непрочитанные уведомления хранятся в SQLite. База должна находиться в постоянной папке `/app/data`.
- При сбое Telegram отправка повторяется при следующей проверке. При длительном простое заказы старше окна `LOOKBACK_DAYS` могут не обнаружиться.
- Бот не изменяет статусы заказов и ничего не подтверждает в кабинете Flowwow.

## Используемый API

- `POST https://apis.flowwow.com/apiseller/shops` — получить ID активных магазинов.
- `GET https://apis.flowwow.com/apiseller/orders/list?shopId=...&createdDate=YYYY-MM-DD&limit=100` — получить список заказов.
- Аутентификация: HTTP-заголовок `Authorization: Bearer <FLOWWOW_TOKEN>`.

**Важно:** проект проверен на синтаксис и смоделированных заказах, но реальное подключение к Flowwow с вашим токеном требует проверки после развёртывания.

## Безопасность

- Ни Flowwow-токен, ни Telegram-токен не должны попадать в GitHub. Используйте секретные переменные Bothost.
- Не загружайте файл `.env` и базу `.db` в публичный репозиторий — они исключены через `.gitignore`.
- Привязка чата разрешена только через `SETUP_CODE` в личных сообщениях.
- Один токен Telegram должен обслуживать только один запущенный экземпляр бота.

## Локальный запуск

Требуется Python 3.10+.

```bash
python -m pip install -r requirements.txt
python main.py
```

Предварительно задайте переменные окружения, указанные в `.env.example`. Сам файл `.env.example` — это образец, он автоматически не загружается.

## Автоматическое отслеживание статусов

- **Опрос Flowwow раз в 30 секунд**, начиная с новой версии. При HTTP 429 пауза увеличивается на время из Retry-After.
- Изменения определяются по официальному полю `status`: 1 — новый, 2 — принят, 3 — завершён, 4 — передан в доставку, 5 — фото до доставки, 7 — ожидает самовывоза, 10/11/12 — почтовые статусы. Неизвестный статус отображается своим кодом.
- После изменения бот **редактирует карточку заказа** в Telegram и **отправляет отдельное уведомление** о переходе. Состояние заказа во Flowwow бот не меняет.
- `message_id` карточки и очередь событий сохраняются в SQLite. При перезапуске история не сбрасывается, если прежняя база сохранена.
- Старые сообщения, отправленные до этого обновления, не имеют сохранённого `message_id`. При **следующем изменении статуса** такого заказа бот создаст новую редактируемую карточку, но не будет повторно рассылать остальные старые заказы.
- Незавершённые заказы старше `LOOKBACK_DAYS` проверяются через `GET /apiseller/orders/view`. Если их больше `MAX_OLDER_CHECKS`, они проверяются по очереди в течение нескольких циклов.
- Возможны пропуски **промежуточных статусов**, если между опросами статус меняется несколько раз. «Курьер назначен» и «Курьер прибыл в магазин» не заявлены отдельными полями схемы заказов открытого API.

### Проверка Telegram без реального заказа

От аккаунта владельца в личном чате или подключённой группе отправьте:

`/teststatus@zakazKiT_bot`

Бот создаст тестовую карточку, **отредактирует её** со статуса «Новый» на «Принят» и отправит тестовое уведомление. Это проверка Telegram; запросов на изменение реального заказа Flowwow нет.

### Автоматические тесты

В GitHub Actions выполняются `compileall` и `unittest` на синтетических данных. Сценарии: миграция базы, редактирование карточек, отсутствие дублей, старые заказы, Telegram-сбои и смена группы.
